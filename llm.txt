# Eduardo's Dotfiles - LLM Context

## Repository Overview
This is a profile-driven dotfiles system for Debian 13 and macOS. One entry point (`install.sh`), one link engine (`scripts/lib/link.sh`), one parity check. Clone, declare the machine's profile in `hosts/<hostname>/PROFILE`, run `./install.sh`.

**Author:** Eduardo Neville
**Primary Target:** Debian/Ubuntu systems
**Philosophy:** Zero-configuration, plug-and-play development environments

## Architecture Patterns

### 1. Symlink-Based Configuration Management
The `scripts/debian/configure_system.sh` script uses symlinks to manage configs:
- Creates symlinks from `~/dotfiles/configs/*` to `~/.config/*`
- **Exceptions:** `ssh` → `~/.ssh/config`; `xinitrc`/`xsession` → `~/.<name>`
- Backs up existing configs with timestamps before overwriting
- Links `.zshrc` and `.gitconfig` directly to home directory
- The link set is derived, not listed: `scripts/lib/link.sh` links every
  `configs/*` directory and every active profile's `configs/*` directory

### 2. OS Detection and Adaptation
`install.sh` sources `scripts/lib/os.sh` (OS + package manager) and
`scripts/lib/packages.sh` (profile package lists), then hands off to
`scripts/$OS/configure_system.sh`:
- Debian 13 → `apt`
- macOS → `brew`
- Profile resolution: `--profile` > `$PROFILE` > `hosts/<hostname>/PROFILE` > `base`

### 3. Install Modes (flags, not a menu)
| command | runs |
|---|---|
| `./install.sh` | apt sources → profile packages → configure → parity |
| `./install.sh --links-only` | skips packages; links + configure + parity |
| `./install.sh --check` | parity only (read-only) |
| `./install.sh --profile base,desktop` | override profile resolution |

The old interactive menu, `--full` and `--unattended` died with
`full_install.sh` (now `deprecated/`). There is no other installer.

### 4. Git Submodules for Shell Plugins
ZSH plugins are vendored as git submodules in `configs/zsh-conf/plugins/`:
- fast-syntax-highlighting
- zsh-autosuggestions
- fzf-tab
- zsh-completions
- zsh-fzf-history-search
This ensures offline installation and version stability.

### 5. Custom Suckless Builds
Both dwm and slstatus are compiled from source:
- Source code in `configs/suckless/`
- Multiple patches included (flextile, nmaster, bartabgroups)
- Custom color schemes and keybindings
- Requires compilation via `profiles/desktop/scripts/build_suckless.sh`
- Sources: `profiles/desktop/configs/suckless/` (not under `configs/`)

## Development Workflow

### Adding New Configuration Files
1. Place config in appropriate subdirectory under `configs/`
2. Nothing to register: `scripts/lib/link.sh` links `configs/*` and
   `profiles/<p>/configs/*` by name
3. Run `./install.sh --links-only` (or `./install.sh`) to apply, then `./install.sh --check`

### Modifying Package Lists
- Profile packages: `profiles/<p>/packages.common` (every OS), `.apt`, `.brew`
- Per-host extras: `hosts/<hostname>/packages.apt`
- Toolchain extras: `opt/{cargoPkgs,nodePkgs,pip,taps.txt,casks.txt,backports.txt}`
- Non-apt installers: `opt/source/` (frozen at nvim+tmux)

### Customizing dwm/slstatus
1. Edit `profiles/desktop/configs/suckless/dwm/config.h` (or `slstatus/config.h`)
2. Run `bash profiles/desktop/scripts/build_suckless.sh` to recompile
3. `./install.sh --check` to confirm the installed binaries are current

### Adding Installation Scripts
1. Create the script in `profiles/<p>/scripts/` (profile-specific) or
   `scripts/$OS/` (adapter-wide)
2. `chmod +x` it
3. Call it from `scripts/$OS/configure_system.sh` — that is the only place
   `install.sh` looks; there is no menu to register it in

## Important File Locations

**Configuration Symlinks Map:**
```
~/dotfiles/configs/<name>/              → ~/.config/<name>       (every dir)
~/dotfiles/profiles/<p>/configs/<name>/ → ~/.config/<name>       (active profiles)
~/dotfiles/configs/ssh/config           → ~/.ssh/config
~/dotfiles/profiles/<p>/configs/xinitrc → ~/.xinitrc
~/dotfiles/profiles/<p>/configs/xsession→ ~/.xsession
~/dotfiles/configs/.gitconfig           → ~/.gitconfig
~/dotfiles/configs/zsh-conf/zshrc       → ~/.zshrc
# no manifest: the set is derived by scripts/lib/link.sh
```

**Package Lists:**
- Profile packages: `profiles/<p>/packages.{common,apt,brew}`
- Per-host extras: `hosts/<hostname>/packages.apt`
- Toolchains: `opt/{cargoPkgs,nodePkgs,pip,taps.txt,casks.txt}`

**Logs:**
- Drift report: `./install.sh --check` (no log file is written)

## Common Tasks

**Full system installation:**
```bash
./install.sh
```

**Links + configure, no package installs:**
```bash
./install.sh --links-only
```

**Read-only drift check:**
```bash
./install.sh --check
```

**Recompile dwm after config changes:**
```bash
bash profiles/desktop/scripts/build_suckless.sh
```

**Install new cargo package:**
```bash
source ~/.cargo/env
cargo install <package>
```

**Update all plugins (ZSH):**
```bash
cd ~/dotfiles
git submodule update --init --recursive
```

**Check audio status:**
```bash
systemctl --user status pipewire wireplumber
pactl list sinks
```

## Troubleshooting Common Issues

**Fonts not displaying:**
```bash
fc-cache -fv
```

**Audio not working:**
```bash
systemctl --user restart pipewire pipewire-pulse wireplumber
```

**Cargo packages failing:**
- Uses `cargo-binstall` for faster installation
- Falls back to compilation

**ZSH plugins not loading:**
```bash
cd ~/dotfiles
git submodule update --init --recursive
```

## Notes for AI Assistants

1. **Always use the symlink approach** when adding new configs - don't directly edit ~/.config files
2. **Check `scripts/lib/link.sh`** before creating symlinks manually
3. **OS-specific scripts** go in `scripts/$OS/` and are called from `configure_system.sh`
4. **ZSH plugins are submodules** - don't try to install via package manager
5. **dwm/slstatus require compilation** — `profiles/desktop/scripts/build_suckless.sh`
6. **Packages are declared per profile** in `profiles/<p>/packages.*` (+ `hosts/<host>/packages.apt`); nothing is installed imperatively
7. **Use modern CLI tools** (eza, bat, fd, rg) instead of legacy tools (ls, cat, find, grep)
8. **Lazy.nvim** is the plugin manager - not Packer (legacy documentation exists but is outdated)
9. **Television** is the fuzzy finder of choice - configure channels in configs/television/cable/
